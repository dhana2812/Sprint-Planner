1.2 Data Flow Pipeline

  1. Structured Input: User supplies concept prompt, target audience, tech stack, sprint velocity (15–60 pts), and risk profile.
  2. Domain Analysis: Keyword scoring classifies the idea into one of 5 domains (AI/ML, FinTech, Collaboration, Security, SaaS).
  3. Decomposition: Generates 6 functional requirements (MoSCoW), 4 non-functional specs, 4 business KPIs, 5 Gherkin user stories, and 16 engineering tasks.
  4. Smart Logic Processing: RICE scoring calculates mathematical priority; Kahn's topological sort determines prerequisite DAG layers and critical path.
  5. Capacity Bin-Packing: Tasks are scheduled into 4 sequential thematic sprints respecting team velocity thresholds.
  6. Persistence & Telemetry: Blueprint state and per-stage latency logs are stored in SQLite.

3. Backend Logic & Smart Logic Layer (Logic Layer — 15%)

SprintForge AI avoids being a simple chatbot wrapper by embedding an explicit mathematical and algorithmic decision-making pipeline:

3.1 Mathematical RICE Priority Scoring

RICE Score = (Reach × Impact × Confidence) / Effort
  • Reach (1–10): Quantifies the volume of users or system touchpoints impacted.
  • Impact (1–10): Strategic business leverage rating.
  • Confidence (50%–100%): Confidence percentage in the architectural scope.
  • Effort (Fibonacci): Mapped to standard Fibonacci story points {1, 2, 3, 5, 8, 13} and converted to engineering hours (6 hrs/pt).
  • Risk Tolerance Buffering:
    • Conservative: Multiplies effort by 1.3 (+30% testing buffer).
    • Aggressive: Multiplies effort by 0.8 (lean fast prototyping).
    • Balanced: Standard 1.0 factor.
  • Priority Tier Mapping: Scores are sorted into quartile tiers: P0 (Critical), P1 (High), P2 (Medium), P3 (Low).

3.2 Topological Sort & Critical Path DAG

Prerequisite task dependencies are parsed using Kahn's Topological Sorting Algorithm:

  • Builds in-degree tracking maps and outgoing adjacency lists.
  • Assigns topological layers (0 = root tasks, 1 = depends on root, etc.) and detects circular dependency cycles.
  • Calculates the Critical Path: the longest weighted path through the project to highlight bottleneck engineering tasks.

3.3 Capacity-Constrained Sprint Bin-Packing

Tasks are scheduled into 4 sequential sprints: Sprint 1: Foundations → Sprint 2: Core Logic → Sprint 3: Interactive Workspaces → Sprint 4: Hardening. Tasks are packed by layer ascending, then RICE score descending, ensuring prerequisite dependencies are never scheduled after dependent tasks and velocity capacity is strictly enforced.

4. Database Design (Database & Admin — 20%)

The platform integrates an embedded relational SQLite database with persistent disk storage at data/sprintforge.db.

4.1 Relational Schema

Table Name Primary Key Columns & Responsibilities
workflows id (TEXT) Stores generated blueprints: title, prompt, target_audience, tech_stack, team_velocity, risk_profile, prd_data (JSON), stories_data (JSON), tasks_data (JSON), sprints_data (JSON), metrics_data (JSON), status, created_at.
execution_logs id (INTEGER AUTO) Tracks per-stage pipeline latency: workflow_id, stage, engine, duration_ms, status, details (JSON), created_at.
system_config key (TEXT) Dynamic configuration: value, description, updated_at. Seeds default velocity, RICE weights, and max sprint buckets.

  • HTML5 Canvas Charts:

  • Dynamic Rule Calibrator: Real-time configuration panel enabling administrators to adjust RICE scoring weights and team velocity capacity live without server restarts.
